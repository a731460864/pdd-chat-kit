# 拼多多商家客服会话模块

> 一个面向拼多多商家客服场景的开源模块：封装登录态维护、会话轮询、消息标准化与文本、图片、视频发送能力。

## 项目简介

拼多多没有提供一套可以直接复用的完整客服会话工具链。对于需要接入自动回复、消息归档或客服工作流的开发者来说，真正耗时的是底层登录态、会话同步、消息类型和发送接口之间的差异。

本模块将这些能力收敛在同一个目录中：

- 通过拼多多商家后台完成登录
- 保存并恢复店铺 Cookie 和身份信息
- 定期获取最新客户会话
- 读取指定客户的历史消息
- 将平台消息码转换为统一类型
- 发送文本、图片和视频
- 过滤系统提示并对消息去重
- 对常见平台错误给出明确提示

模块只负责拼多多平台能力，不绑定具体业务规则或上层应用。

```text
拼多多商家后台
      │
      │ 登录 / 会话接口
      ▼
拼多多会话模块
      │
      │ 标准消息对象
      ▼
调用方的处理逻辑
      │
      │ 回复文本 / 图片 / 视频
      ▼
拼多多商家后台
```

## 工作流程

```text
1. 使用拼多多商家账号登录
2. 获取 Cookie、mallId 和 anti-content
3. 每 5 秒请求一次最新会话
4. 过滤平台系统提示
5. 检查最后一条消息是否来自客户
6. 使用消息 ID 判断是否为新消息
7. 将消息转换为统一类型
8. 交给调用方处理
9. 根据处理结果发送文本、图片或视频
```

模块不会把首次启动前的大量历史会话全部重新输出。新的会话只有在未读或最近产生消息时才会进入处理流程。

## 消息类型

拼多多原始消息码会被转换为稳定的统一类型：

| 拼多多类型码 | 统一类型 | 当前用途 |
| --- | --- | --- |
| `0` | `text` | 文本消息 |
| `1` | `image` | 图片消息 |
| `2` / `14` | `video` | 视频消息 |
| `3` / `4` / `64` | `product` | 商品卡片与商品上下文 |
| `24` / `30` / `40` / `43` | `system` | 系统消息 |
| `5` | `emoji` | 表情消息识别 |
| `1002` | `other` | 其他类型 |

商品消息还可以提取：

```js
{
  goods_id: '',
  goods_name: '',
  goods_price: null,
  goods_thumb: '',
  goods_spec: '',
  goods_link: ''
}
```

## 快速开始

### 环境要求

- Node.js 18+
- 支持 Chromium/Electron 浏览器页面的运行环境
- 已授权的拼多多商家账号

底层 HTTP 会话接口依赖 Node.js 18 提供的 `fetch`、`AbortSignal.timeout` 等能力。

### 使用已有会话读取消息

准备店铺会话对象：

```js
const store = {
  cookies: [
    { name: 'cookie_name', value: 'cookie_value' }
  ],
  anti_content: '...',
  mallId: '...'
}
```

读取最新会话：

```js
const conversations = await api.getConversations(store)
```

读取指定客户的历史消息：

```js
const messages = await api.getHistory(store, customerUid, 50)
```

发送文本：

```js
await api.sendText(store, customerUid, '您好，请问有什么可以帮您？')
```

发送图片或视频：

```js
await api.sendImage(store, customerUid, 'https://example.com/image.jpg')
await api.sendVideo(store, customerUid, 'https://example.com/video.mp4')
```

> 图片和视频必须使用平台可访问的 HTTP 地址，不能直接填写本地文件路径。

## 适配器接口

核心适配器提供四个主要方法：

```js
connect(options)          // 登录或恢复已保存的店铺
poll(store)               // 获取新增客户消息
send(conversation, item)  // 发送文本、图片或视频
handleChatRequest(req)    // 获取会话列表或历史记录
```

### `connect(options)`

- 使用账号密码打开拼多多登录页并自动填写
- 识别验证码、滑块或短信验证
- 登录成功后读取 Cookie、店铺 ID、名称和 Logo
- 支持手动登录和已保存店铺恢复

### `poll(store)`

- 获取最新会话
- 获取增量历史消息
- 过滤系统提示
- 按消息 ID 去重
- 返回统一格式的客户消息

### `send(conversation, item)`

- `text`：发送文本
- `image`：发送图片网络地址
- `video`：发送视频网络地址
- 不支持的类型会返回明确错误

### `handleChatRequest(req)`

- `chat_get_conversations`：读取会话列表
- `chat_get_history`：读取指定客户历史消息

## 登录态设计

每个店铺至少需要保存以下数据：

| 字段 | 用途 |
| --- | --- |
| `cookies` | 请求商家后台接口 |
| `mallId` | 标识拼多多店铺 |
| `anti_content` | 拼多多会话请求校验字段 |
| `store_name` | 展示店铺名称 |
| `logo` | 展示店铺头像 |

会话对象由调用方保存。模块本身不上传 Cookie，也不内置远程存储。

### 自动恢复

1. 打开拼多多商家后台检查页面状态
2. 如果仍处于登录状态，刷新 Cookie 和 `anti-content`
3. 如果被重定向到登录页，尝试使用已保存账号密码登录
4. 如果出现验证码或滑块，等待用户手动完成
5. 自动恢复失败时返回明确的重新登录提示

## 错误处理

| 平台错误 | 含义 | 建议处理 |
| --- | --- | --- |
| `43001` | 会话已过期，登录态失效 | 重新登录或更新 Cookie |
| `40001` | 参数错误或消息内容不支持 | 检查内容、媒体地址和客户 ID |
| `54001` | 被平台限制 | 降低频率并稍后重试 |
| HTTP 非 JSON 响应 | 接口被拦截、登录失效或平台改版 | 保存响应状态并重新检查会话 |
| 连续轮询失败 | Cookie 或商家后台状态异常 | 执行登录状态检查并尝试恢复 |

## 安全说明

- 只使用已授权的拼多多商家账号
- Cookie 和账号凭据属于敏感信息，不应提交到公开仓库
- 日志中不要输出完整 Cookie、密码或 `anti-content`
- 图片和视频地址应使用可公开访问或带有效期的 HTTPS 地址
- 验证码、滑块和账号安全验证必须由账号持有人完成

---

## 使用边界

- 本模块依赖拼多多商家后台的页面和接口，不是拼多多官方开放平台 SDK
- 平台页面结构、请求字段或风控策略变化后，可能需要同步维护适配代码
- 当前不提供表情回复和语音发送
- 不支持绕过验证码、账号验证或平台安全机制
- 请仅用于合法授权的商家客服场景，遵守拼多多平台规则和适用法律
